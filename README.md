# Music DSL

텍스트 기반으로 피아노 음악을 표현하기 위한 간단한 DSL(Domain Specific Language)입니다.

이 DSL은 사람이 직접 악보를 그리는 대신, 텍스트 형태로 음악을 작성한 뒤 이를 프로그램이 파싱하여 MusicXML, MIDI, 악보 등으로 변환하는 것을 목표로 합니다.

특히 AI가 음악을 생성하기 쉽도록 설계되었습니다.

## 현재 구현

이 저장소에는 Python 기반 Music DSL 변환기가 포함되어 있습니다.

- DSL 파일을 파싱합니다.
- 오른손(`RH`)과 왼손(`LH`) 트랙을 분리합니다.
- MusicXML 4.0 partwise 형식으로 내보냅니다.
- `RH`는 MusicXML part `P1`, `LH`는 `P2`로 출력합니다.
- 4/4 박자와 `@unit: 1/16` 기준으로 마디를 자동 계산합니다.
- 마디 경계를 넘는 음은 tie로 분할합니다.
- 같은 슬롯에서 시작하는 여러 음은 chord로 출력합니다.
- 빈 슬롯은 rest로 출력합니다.
- MusicXML의 `<duration>`뿐 아니라 `<type>`도 음 길이에 맞게 출력합니다.
- 3연음(`T3[...]`)은 MusicXML의 `<time-modification>`과 `<tuplet>`으로 출력합니다.
- 잇단음표를 정확히 표현하기 위해 MusicXML `divisions`는 12를 사용합니다. DSL의 슬롯 의미는 그대로 유지되며, 1슬롯은 여전히 16분음표입니다.
- `@Chord` 섹션의 코드 심볼(`C`, `Am`, `G/B` 등)은 MusicXML의 `<harmony>`로 출력합니다.

## 실행

기본 입력 파일은 `input.dsl`입니다.

기본 출력 파일은 `output.musicxml`입니다.

```bash
python -m simpledsl
```

입출력 경로를 직접 지정할 수도 있습니다.

```bash
python -m simpledsl input.dsl output.musicxml
```

또는 루트의 `main.py`로 실행할 수도 있습니다.

```bash
python main.py input.dsl output.musicxml
```

## 핵심 개념

### 1. 세미콜론(`;`)은 시간 슬롯입니다

세미콜론 하나는 최소 시간 단위(slot)를 의미합니다.

예를 들어:

```text
@unit: 1/16
```

이면:

```text
;
```

하나는 16분음표 한 칸입니다.

따라서:

```text
;;;;
```

은 16분음표 4개, 즉 4/4 기준 1박입니다.

## 음표 표기법

### 기본 형식

```text
음이름옥타브-지속슬롯수
```

예시:

```text
C4-4
D#5-2
Bb3-8
```

| 표기 | 의미 |
| --- | --- |
| `C4` | C 음, 4옥타브 |
| `-4` | 4 슬롯 동안 지속 |
| `D#5` | D# 음, 5옥타브 |
| `Bb3` | Bb 음, 3옥타브 |

### 장식음

음표 뒤에 `~tr`을 붙이면 트릴로 표시합니다.

예시:

```text
D6-4~tr
```

MusicXML에서는 `<trill-mark/>`로 내보냅니다.

### 코드 섹션

코드 심볼은 `@Chord` 섹션에 따로 씁니다. 코드 진행은 RH/LH 선율과 독립적으로 파싱되고, MusicXML에서는 RH 파트 위의 `<harmony>`로 출력됩니다.

```text
@Chord
C | G | Am | F
C/E | G | Am | C
```

의미:

- `|`는 다음 마디로 넘어갑니다.
- 줄바꿈도 다음 마디 진행을 계속합니다.
- 한 마디에 코드 하나만 쓰면 해당 마디 첫 슬롯에 표시됩니다.
- 한 마디 안에서 코드가 바뀔 때만 세미콜론으로 위치를 구분합니다.

예:

```text
@Chord
C;;;;;;;;G/B | Am;;;;;;;;F
```

4/4와 `@unit: 1/16` 기준으로 첫 마디에는 `C`가 `slot 0`, `G/B`가 `slot 8`, 즉 3박 위치에 표시됩니다. 둘째 마디에는 `Am`과 `F`가 같은 방식으로 표시됩니다.

공백으로 여러 코드를 나란히 쓰는 방식은 지원하지 않습니다. 마디 안에서 위치가 달라지는 코드 변경은 세미콜론으로 명시해야 합니다.

지원 예:

```text
C
Am
Fmaj7
G7
Dm
G/B
```

### 3연음

`T3[...]`는 현재 슬롯에서 시작하는 3연음 그룹입니다.

```text
T3[E5,F5,G5]-4
```

의미:

- `E5`, `F5`, `G5`가 순서대로 연주됩니다.
- 전체 그룹은 4 슬롯, 즉 4/4 기준 1박을 차지합니다.
- 세 음은 MusicXML에서 8분음표 3연음으로 표시됩니다.
- 시간 커서는 일반 음표와 마찬가지로 자동으로 그룹 길이만큼 이동하지 않습니다. 다음 음을 한 박 뒤에 두려면 `;;;;`를 써야 합니다.

예시:

```text
T3[E5,F5,G5]-4;;;;C6-4;;;;
```

지원 범위:

- 현재는 `T3`만 지원합니다.
- 그룹 안의 음은 쉼표 없이 피치만 씁니다.
- 구분자는 쉼표나 공백을 사용할 수 있습니다.

## 시간의 흐름

세미콜론(`;`)이 등장하면 현재 시간이 1 슬롯 전진합니다.

예시:

```text
C4-4;;;;E4-4;
```

의미:

- `C4`는 현재 시점(slot 0)에서 시작합니다.
- `C4`는 4 슬롯 동안 지속됩니다.
- `;;;;`로 시간이 4 슬롯 이동합니다.
- `E4`는 slot 4에서 시작합니다.

## 화음(동시발음)

같은 세미콜론 이전에 등장한 음들은 동시에 시작합니다.

예시:

```text
C4-8E4-8G4-8;
```

의미:

- `C4`, `E4`, `G4`가 동시에 시작합니다.
- 모두 8 슬롯 동안 지속됩니다.
- 하나의 화음(chord)을 형성합니다.

## 서로 다른 지속시간

같은 시점에 시작하더라도 각 음의 길이는 다를 수 있습니다.

예시:

```text
C4-8E4-8G4-4;
```

| 음 | 지속시간 |
| --- | --- |
| `C4` | 8 슬롯 |
| `E4` | 8 슬롯 |
| `G4` | 4 슬롯 |

즉 `G4`만 먼저 끝납니다.

## 쉼표(Rest)

빈 슬롯은 쉼표로 간주됩니다.

예시:

```text
;;;;
```

의미:

- 4 슬롯 동안 아무 음도 없습니다.
- 즉 1박 쉼표입니다. 4/4와 16분음표 슬롯 기준입니다.

## 메타데이터

메타데이터는 `@`로 시작합니다.

예시:

```text
@title: My Song
@unit: 1/16
@tempo: 120q
@time: 4/4
@key: C
```

| 메타 | 의미 |
| --- | --- |
| `@title` | 곡 제목 |
| `@unit` | 슬롯 단위 |
| `@tempo` | BPM |
| `@time` | 박자표 |
| `@key` | 조성 |

## 트랙

피아노곡의 경우 오른손과 왼손을 분리하여 표현합니다. 코드 심볼은 `@Chord` 섹션에서 별도로 표현합니다.

예시:

```text
@Chord
C | G

@track: RH
C5-4;D5-4;E5-4;

@track: LH
C3-8;;;;G2-8;;;;
```

| 트랙 | 의미 |
| --- | --- |
| `RH` | 오른손(Right Hand) |
| `LH` | 왼손(Left Hand) |
| `@Chord` | 코드 심볼 진행 |

RH/LH는 각각 독립적인 시간축을 가집니다. `@Chord`는 마디 단위 코드 진행을 가지며, `@time`과 `@unit` 기준으로 위치가 계산됩니다.

## 마디 계산

예를 들어:

```text
@unit: 1/16
@time: 4/4
```

이면:

- 1 슬롯 = 16분음표
- 1마디 = 16 슬롯

프로그램은 이를 기반으로 자동으로 마디를 계산할 수 있습니다.

## 전체 예시

```text
@title: Simple Example
@unit: 1/16
@tempo: 96q
@time: 4/4
@key: C

@Chord
C | G | Am | F

@track: RH
C5-4;D5-4;E5-4;G5-4;

@track: LH
C3-8;;;;G2-8;;;;
```

## 설계 목적

이 DSL은 다음 목적을 위해 설계되었습니다.

- 텍스트 기반 음악 표현
- AI 음악 생성
- MIDI 변환
- MusicXML 변환
- 악보 자동 생성
- 간단한 파싱
- 사람이 직접 수정 가능한 구조

## 특징

### 장점

- 사람이 읽기 쉽습니다.
- AI가 생성하기 쉽습니다.
- 파싱이 단순합니다.
- 화음 표현이 쉽습니다.
- 지속시간 표현이 직관적입니다.
- MIDI 이벤트 모델과 잘 대응됩니다.

## 철학

이 DSL은 전통 악보 자체를 대체하려는 것이 아니라,

```text
텍스트 → DSL → MusicXML/MIDI → 악보
```

와 같은 중간 표현(intermediate representation)을 목표로 합니다.
